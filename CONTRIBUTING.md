# Contributing

This repository uses an orchestrator/implementer workflow: Claude Fable 5 owns planning and architecture, writes a precise task specification, delegates implementation to Codex CLI running `gpt-5.6-sol` with `xhigh` reasoning (for example, `codex exec -m gpt-5.6-sol -c model_reasoning_effort=xhigh "<task spec>"`), then reviews the diff and runs the relevant checks; Codex performs the implementation, and any rework returns with concrete feedback while only trivial fixes are hand-edited. A task specification should state the goal, files or systems in scope, constraints, and observable acceptance criteria; the implementer report should summarize the outcome, list material files changed, give the exact verification performed and results, and call out any remaining risks or decisions. Do not commit unless the task explicitly asks for it.
